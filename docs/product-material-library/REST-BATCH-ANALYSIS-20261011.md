## 3. ② 401 条来源链接存活探测（脚本 `O/r13/rest-link-liveness.mjs`，回执 `evidence/rest-link-liveness.json`）

- **做法**：只读探测——`HEAD` 优先；若返回 400/403/405/501 才降级为 `GET` + `Range: bytes=0-0`（只取 0 字节，响应体丢弃）；并发 8、单条超时 5s、**硬上限 500 次请求**。**未登录、未下载正文或媒体、未写入任何平台。**
- **结果（401/401 全部有结论）**：

| 平台 | 条数 | 活 | 死 | 未知 |
| --- | --- | --- | --- | --- |
| Douyin | 284 | **284** | 0 | 0 |
| TikTok | 110 | 0 | 0 | **110** |
| YouTube | 7 | 0 | 0 | **7** |

  - 状态分布：`200` 131 条、`302` 153 条（均判为**活**）、`超时` 117 条（判为**未知**）。
  - **整体存活率 70.8%，95% 置信区间 [66.4%, 75.3%]**（分母＝401）。
  - **失败原因全部是"超时"**：本机网络环境下 `tiktok.com` 与 `youtube.com` **连不上**（用 curl 直接验证同样是 `000/超时`）；这与"链接已失效"**不是一回事**，因此这 117 条一律记 **unknown，不猜**。

## 4. 这批数据的处理建议（按性价比排序）

1. **现在就能做（零成本、零授权）**：用指标层做**趋势/对标**，样本限定"有数值"的记录；结论输出到面板或分析页，供选品与内容方向参考。
2. **低风险先探再定（只读）**：Douyin 那 **284 条**链接**全部还活着**，若要"补成有视频+有分镜"，**优先从这批开始**；TikTok/YouTube 的 117 条必须先解决**网络可达性**（否则连探测都做不到）。
3. **需要批准才做**：真正的**重新采集**（下载视频、抓取分镜/文本）属于新增采集，工单目前禁止；建议按"284 条 Douyin 优先 → 分批、可停可续、每批留回执"的方式申请。
4. **不建议**：对 1,927 条整体重采（1,500 余条连链接都没有，重采无从下手）。

## 5. 局限（必须一起读）

- 存活探测只证明"**能连上**"，**不证明内容还在、也不证明可下载**（平台可对未登录请求返回登录页）。
- 本机对 TikTok/YouTube 不可达 ⇒ 这两个平台的链接结论是"**本机不可判**"，不构成业务结论。
- 指标层分母口径已在回执里逐条写明；跨平台的"播放/点赞"定义不同，**不可直接横比**。
